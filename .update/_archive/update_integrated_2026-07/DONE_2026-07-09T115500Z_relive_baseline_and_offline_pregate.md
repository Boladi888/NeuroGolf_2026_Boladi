# Transferable insight — on a mature task, RE-DECODE THE LIVE ONNX before trusting the task .md floor; and offline-200k pre-gate ambiguous-class candidates

**Source**: task158 batch 2026-07-09 (`bo_ng_cld_worker2`). Outcome: **staged v128 = 22,550 (−651 vs LIVE 23,201, byte-equal to LIVE)** — the offline 200k pre-gate DIRECTLY surfaced the win (a bench variant that matched LIVE's argmax at 0/200k pointed to a droppable plane). Two other routes walled with the same tooling. Full record: `The_400_Tasks/Task_by_Task/task158/hard_records/floor_and_dead_routes_22550.md`.

## The win the pre-gate found — a rank-only bonus does not need its magnitude
LIVE scored legend windows `score = nbsum + g16`, `g16 = Where(gW, 16, 0)` (a +16 bonus so multicolor windows outrank single-color). But `score` is consumed ONLY by `ReduceMax→ArgMax`. The argmax needs multicolor windows *ranked above* single-color — NOT the additive +16. So `score = Where(gW, nbsum, 0)` (gate single-color to 0) is argmax-identical and drops the whole `g16` plane (650 B) + its constant param. **General pattern: when a computed value feeds only an argmax/comparison, any monotone-rank-preserving simplification is free — strip additive/scale constants that only separate classes the ranking already separates.** Watch the ORT-legal encoding: `nbsum·multicolor` needs `Mul(U8,U8)` (banned here) but the identical values come from `Where(BOOL,U8,0)` (legal). I almost walked away from this because I equated the idea with the banned Mul.

## Trap avoided — the local task .md described a SUPERSEDED graph family
task158's `.md` (Cost analysis, floor proofs, Attempts) documented a v125 candidate at 23,460: F32 output via `Where(paint_mask,paint,input)`, dense per-scale `s1/s2/s3` valid-score planes, "convolutional-family floor ~24k", and the prompt's `floor_est ~11000` ("three dense valid-score planes are the family wall"). **None of that is LIVE.** The manifest team-best (23,201, owner Sho, sha `cd08cc20468a…`) is a *different, undocumented formulation*: BOOL one-hot output via a free `Equal(colorid,[colors])` tail, everything cropped to the 26×25 max-active grid, ONE `QLinearConv[3,2,11,11]` detection + ONE `ConvInteger[1,3,9,9]` gather-render. Sho had already collapsed the "dense s1/s2/s3" the prompt told me to attack — they don't exist in LIVE. Attacking the documented family would have been pure waste.

**Rule: on any mature/structural task, the FIRST action is to decode the actual live team-best ONNX, not read the task .md floor analysis.** `tools/ng_current_bar.py --task N --json` → get the live sha/path → `inspect_graph.py <live.onnx>` + `profile_real_cost.py` + `largest_intermediate.py` on the LIVE file. Only then read the .md, and treat its "floor proof" as possibly-stale if the live sha post-dates it. The .md `## COMPRESSED HISTORY`/floor prose is written against whatever was live at write-time; a later ship by another agent silently invalidates it. (Add a STALE-DOCS flag to the .md when you find this, as I did.)

## Technique — offline 200k pre-gate for ambiguous-class (byte-equal-to-LIVE) tasks
When `truth` on the LIVE extract is <100% (task158: 199,926/200,000), the ship gate is **byte-equal-to-LIVE on the full AB corpus**, not 100% truth. That means a candidate is feasible **iff it reproduces LIVE's exact output on every corpus pair** — which is fully testable OFFLINE, before any heavy gate:
1. Find the pivotal intermediate that determines the output. Here the whole ~8,450 B legend locator (`score` plane) feeds only `ReduceMax→ArgMax` → legend centre `(rc,cc)`; the output depends only on that argmax, not the score values.
2. Instrument LIVE: append the intermediate(s) as extra graph outputs (set concrete `elem_type`, UNDEFINED=0 is rejected), `onnx.utils.Extractor(...).extract_model(["input"],[names])` to prune the render (LIVE's `Gather 'gat'` crashes on ~74/200k pairs — extract past it), run on the cached corpus (`tools/ng_harness/corpus.get_tensors/iter_tensors`, seed_offset matches the gate).
3. Build a numpy replica of that stage, **byte-validate it == ORT on ~5k first**, then bench candidate simplifications' `(rc,cc)` agreement vs LIVE over the **full 200,000**. A variant matching all 200k = passes `ab --full` by construction → high confidence with zero heavy-gate burn. task158 result: `nbsum`-only mislocates 48,818/200k (bonus load-bearing); argmax-preserving variants save 0 tensors.

## Technique — proving a "floor" by TENSOR-MINIMALITY (not "tried hard")
To declare a graph the floor: expose ALL intermediates over a corpus sample and check (a) any two same-shape tensors ALWAYS byte-equal (redundant → deletable) and (b) any F32/INT32 tensor whose values always fit a smaller dtype. task158 hunt (`prototypes/_redundancy_hunt.py`): 0 redundant pairs; only `cidc`(F32, 0..9) and `CP`(INT32, 0..76) were dtype-slack — but both **dtype-forced** (`cidc` is a `Conv` output = float-only; `CP` is `ConvInteger` output = INT32-only, consumed as a `Gather` index = int-only). Then argue each remaining tensor is consumed and its dtype/shape forced by an ORT op constraint or by data-dependence. This is a *checkable* floor proof.

## ORT / scorer facts reconfirmed
- Output tensor of the graph is **NOT charged** (memory = Σ intermediate bytes only). Emit a single U8 colorid plane and expand to the required `[1,10,H,W]` BOOL one-hot for FREE via `Equal(colorid[1,1,H,W], colors[1,10,1,1])` — the one-hot output costs 0. (task158 LIVE does this.)
- Crop every plane to the corpus max-active grid via negative `Conv` pads (`[0,0,-4,-5]` → 30×30→26×25); a single `Pad` back to 30×30 only at the very end for the output broadcast. ~250 B/plane × ~20 planes saved vs working at 30×30.
- Data-dependent stamp/paint PATTERN (task158: 18 distinct legend paint-cell patterns over 4,000 legends) forces a runtime `Gather` render (INT32 index) — a static conv paint-mask cannot render it. Confirms #132 (conv/gather floor, not separable/static-mask floor). `Mul(U8,U8)` still ORT-banned here.
