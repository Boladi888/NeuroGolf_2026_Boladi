## Gates (ALL before staging a primary)
1. `ng_gate visible --task N --cand X.onnx` — must be 100%. **One visible miss = certain hidden 0 (traps §VISIBLE-FAIL AXIOM)** — abandon the candidate.
2. `ng_gate truth --task N --full` — 200k corpus. If LIVE itself is <100% (run truth on the LIVE extract FIRST — traps §CLASS-CHECK), the task is ambiguous-class: byte-equal-vs-LIVE replaces 100%-truth as the gold gate. **Slow model? compute per-pair ms × 2k before fearing timeouts; gate with `--n 20000` and note the cap.**
3. `ng_gate ab --task N --full` — byte-equal vs LIVE = gold ship class. Divergences → §DUAL-TRUTH attribution (run truth on BOTH; `ab_divs == LIVE_misses − cand_misses` ⇒ more-correct-than-LIVE, shippable).
4. Cost: `tools/_score_v2.py` — **STATIC graphs price EXACTLY (§39 MECHANISM); any dynamic shape/dummy-branch/optional-input makes local cost FICTION (78× seen)** — build static, stage a boring-static sibling beside any exotic rung.
5. **REAL-INPUT PROFILE (mandatory since 2026-06-07, the task225 reprice)**: before staging, run your candidate over the REAL officials with ORT profiling and compute the §39 `max(static, runtime)` per tensor — the result IS the credited cost. task225's "byte-equal, static-looking" 743 credited at ~2,160 (2.9×) because an unflagged runtime surface inflated; task360's worker measured 358→6,442 locally and saved the surprise. Record `profile_cost` in the manifest next to `score_v2` cost; any gap >5% = flag the rung as a credit-probe, not an exact ship.
