# Latent Correspondence and Assignment Algorithms for Static ONNX

**Target basename:** `Research/Done/o5_latent_correspondence_assignment_algorithms.md` [PROMPT]

## Scope and framing

The key constraint on this card is not asymptotic complexity alone. It is **static-compilability into a loop-free ONNX DAG** with fixed tensor shapes, on ONNX Runtime 1.24.4 CPU, under a cost model dominated by intermediate bytes plus parameter elements. In that regime, many “good” classical algorithms become poor fits because their efficient forms rely on data-dependent iteration, alternating-tree growth, shortest-path augmentation, or convergence to a stopping condition. By contrast, small dense `N x N` tensors are cheap when `N<=10`, while anything that expands across `H,W` or materializes higher-order pair structures can become expensive very quickly. [PROMPT][DERIVED] citeturn2search0turn17view0turn25search0

A second framing point is that **matching is often unnecessary**. If the generator already provides a scalar key that uniquely orders objects or slots, then sorting or ranking is cheaper and cleaner than a full assignment solver. That observation is especially important here because ONNX already gives deterministic tie behavior for ranking primitives: `TopK` breaks equal values by lower index first, and `ArgMax`/`ArgMin` pick the first occurrence by default unless `select_last_index` is changed. ## Static-DAG transfer test

For **Hungarian and JV-style linear assignment**, the tensor shapes are not the problem. A fixed `C[N,N]` cost matrix, row/column dual labels, visit masks, predecessors, and current assignments all have static size. The real problem is that the solver’s power comes from **data-dependent alternating-path growth** and repeated augmentation. A static graph can emulate this only by unrolling the worst-case number of relaxation and augmentation phases and carrying masks through every branch. That preserves static shapes, but it produces a graph that is much more complex than the project’s current pairwise matrix idioms. [PRIMARY][DERIVED] citeturn28search0turn17view0turn20search0

For **stable matching**, the situation is much better. One can encode both sides’ full preference lists or rank matrices in static `N x N` tensors, hold a proposal pointer for each proposer, and unroll exactly `N^2` proposal rounds. Each round proposes to the next-ranked acceptable partner, groups competing proposals by recipient, keeps the best proposer under the recipient’s ranking, and advances the rejected proposers. All tensors remain static, and the control structure is simple because the worst-case proposal budget is known in advance from the model itself. The catch is objective mismatch: the result is a stable matching, not a minimum-cost assignment. citeturn19search0turn4search3

For **auction algorithms**, transfer is easy only if one is willing to accept approximation. A fixed-round graph can repeatedly update bids and prices on a small `N x N` matrix, but exact convergence is fundamentally tied to a stopping condition that depends on the instance and, in the classical theory, on the `\epsilon` schedule. That is exactly the sort of adaptive iteration the card disallows. So auction is transferable as a heuristic layer, not as a clean exact solver family for this environment. citeturn22search2turn7academia51

For **bottleneck assignment**, the static tensor plan is “threshold first, solve feasibility second.” Build a small set of candidate thresholds from the finite edge costs, form `C<=t` masks, and ask whether a perfect matching exists at each threshold. The threshold scan itself is static and cheap. The hard part is still the perfect-matching subsolver. So bottleneck assignment is only as ONNX-friendly as the exact feasibility routine embedded inside it. Without a non-augmenting-path exact core, it does not become easier than ordinary LAP. citeturn5search2turn5academia36

For **graph matching / QAP**, static shapes are again possible but expensive. Unary matching lives in `N x N`, while relational consistency naturally introduces association objects of size `N^2 x N^2`. At `N=10`, that is still not enormous in absolute memory, but it is already far larger than a plain cost matrix and normally feeds into an iterative approximate optimizer such as FAQ or `2opt`. That makes it the least attractive transfer unless the hidden-task rule genuinely depends on pairwise structure that unary ranking cannot capture. [PROMPT][PRIMARY][DERIVED] citeturn25search0turn18search0

For **Sinkhorn-style soft assignment**, transfer is straightforward. Start from an `(N+1) x (N+1)` score matrix if rejection is needed, run a fixed `K` row/column normalization schedule, then harden by `ArgMax` or `TopK`. That is tiny, regular, and fully static. It is also philosophically close to the project’s existing `(K+1)` noop-bin approach, except that it enforces a soft one-to-one structure before hardening. The weakness is exactness: the relaxed OT plan need not harden to the true discrete optimum. citeturn7search3turn13academia21turn14academia21

The most important **derived** transfer is a **subset-state exact linear-assignment dynamic program**. A Bellman-style finite-horizon view assigns rows one at a time and stores the best cost for each used-column subset. With `N=10`, there are only `2^10 = 1024` subsets. That means a static DAG can propagate a `dp[1024]` vector through `N` stages, materializing at worst a `1024 x N` transition slab before a reduction at each stage. The shapes are fixed, the selection logic is simple, and the method solves the actual global one-to-one objective. Relative to unrolled Hungarian/JV, this is the cleanest exact static reformulation I found. [PRIMARY][DERIVED] citeturn26search1turn17view0

## Cost comparison

The most important cost comparison is against the incumbents already named in the card: pairwise comparison rankers, `TopK`, `ScatterElements` routing, noop bins, and slot-wise one-hot banks. Those incumbents are extremely strong whenever the task reduces to direct indexing, scalar-key ordering, or unique color/size/position cues. In those cases, a full matching layer is paying for global structure that the task does not need. [PROMPT][DERIVED] citeturn1search0turn24view0

## Exactness and tie rules

For this card, exactness needs two parts: the solver must optimize the intended objective, and it must have an **explicit deterministic tie policy**. Classical LAP methods satisfy the first part but not automatically the second, because multiple assignments can share the same optimum value. In a static ONNX graph, the cleanest deterministic policy is to inject a fixed lexicographic perturbation or fixed row/column priority into the score matrix before solving. If hardening passes through `TopK`, `ArgMax`, or `ArgMin`, ONNX’s own default tie rules then make the output deterministic. [PRIMARY][DERIVED] citeturn1search0turn9search1turn9search0

Stable matching has a different semantics. Under strict preference orders and fixed proposer side, Gale–Shapley is exact and deterministic for the **stable-matching** objective. But that objective is not the same as minimum-sum or minimum-bottleneck assignment. So it is “exact” only if stability itself is what the task needs, not if it is merely being used as a proxy collision resolver. citeturn19search0turn4search3

Auction and Sinkhorn are exact only in restricted senses. Auction becomes exact only if allowed to run to its proper convergence condition, which this environment cannot express naturally. Sinkhorn is exact for the relaxed entropic transport problem it solves, but a subsequent hardening step can disagree with the true discrete optimum. That makes both families useful approximate transfers, but not deterministic exact replacements for the linear assignment families. citeturn22search2turn13academia21turn7search3

Final routing collision behavior also matters. `ScatterElements` with `reduction="none"` expects there to be no duplicate target indices; duplicate writes are well-defined only when a reduction such as `add`, `mul`, `max`, or `min` is chosen. So any assignment layer that can emit duplicate slots is not exact unless collision prevention happens **before** scatter, or unless the reduced scatter itself is the intended mathematical operation. That is a strong practical reason to favor assignment formulations that produce genuine one-to-one outputs before routing. citeturn24view0

## Probe shortlist and blunt verdict

The **best exact probe** is a **subset-state exact linear-assignment dynamic program** compiled as a fixed `2^N` state lattice for small `N`. [DERIVED][SPECULATIVE] It is not one of the classical named software solvers, but under the static-DAG constraints it is more plausible than unrolled Hungarian/JV because it avoids data-dependent augmenting-path control while still solving the actual global one-to-one objective. It is the one probe from this whole survey that looks capable of beating current local-routing idioms when the hidden rule genuinely depends on exact global collision resolution. [DERIVED] citeturn26search1turn17view0

The **best cheap approximate probe** is a **fixed-iteration Sinkhorn layer with one reject slot**. [SPECULATIVE] Its tensor footprint is tiny, its static unroll is trivial, and it is directly comparable to the project’s existing noop-bin and slot-bank patterns. The right evaluation question is not whether it is exact, but whether a small soft one-to-one relaxation reduces collision brittleness enough to improve hidden-test generalization. citeturn13academia21turn14academia21

The repo-access probes worth running are therefore narrow and practical. [SPECULATIVE] Use a trusted LAP baseline such as SciPy’s `linear_sum_assignment` as the software reference for exact linear assignment, since SciPy documents that implementation as a modified Jonker–Volgenant solver. Use SciPy’s `quadratic_assignment` FAQ implementation only on deliberately relation-heavy analogy tasks, because it is approximate and much more expensive. For learned approximate matching with unmatched handling, inspect the public SuperGlue paper and repo as the canonical compact OT-style reference. citeturn17view0turn25search0turn15search0

**Blunt verdict:** current slot-routing techniques still dominate whenever the task reduces to sorting, ranking, direct slot indexing, or unique histograms/coordinates. [PROMPT] If one assignment-family probe is worth the engineering cost, it is **the derived subset-state exact LAP DP**, not Hungarian, not auction, and not graph matching. If one approximate correspondence probe is worth trying, it is **fixed-iteration Sinkhorn with a reject slot**. Everything else surveyed here is either statically awkward, too expensive for its likely gain, or solving the wrong objective. [DERIVED] citeturn13academia21turn17view0turn25search0
