# spatial_rearrangement.md — DepthToSpace, SpaceToDepth, Resize, ReverseSequence

Four ops that rearrange the data layout of a tensor without arithmetic. All are 0-MAC under `onnx-tool`. Useful when you need to swap channels↔spatial, replicate cells, or reverse along an axis.

> **Related:** For flips, rotations, and arbitrary affine warps — see `symmetry_and_affine.md`. That doc covers `Slice(steps=[-1])` (the cheapest axis-reversal primitive), `Transpose` for diagonal reflection, and `GridSample` for fixed-shape dihedral-transform graphs.

---

## DepthToSpace **[opset 1, mode="DCR" default; opset 11 added mode="CRD"]**

Rearranges `[N, C·r², H, W]` → `[N, C, H·r, W·r]`. "Promotes" channel data into spatial resolution.

```
DepthToSpace(input)
attributes:
  blocksize: int (required) — the r
  mode: "DCR" (default) or "CRD"
```

### Mode difference (the part Sonnet always forgets)

For `blocksize=2`, input channels `[c0, c1, c2, c3, c4, c5, c6, c7]` map to output 2×2 tile in two different ways:

**DCR** ("Depth-Column-Row"): channels grouped as `(c0, c1, c2, c3)` for first output channel, `(c4, c5, c6, c7)` for second. Within each group:
```
[c0, c1]
[c2, c3]
```

**CRD** ("Column-Row-Depth"): channels grouped as `(c0, c1, c2, c3)` for first output channel, same layout. Within each group, ordering may differ; CRD is the "PyTorch-style" interleaving.

**[ASSUMED]**: For most ARC-style grid tasks, both work because you're treating it as a pure data permutation. Pick one consistently and verify visually with a known test pattern.

### NeuroGolf use cases

**1. Compactify spatial into channels for cheap "patches":**

If you have a `[1, 10, 30, 30]` tensor and want to operate on 2×2 patches as 4-channel groups:

```python
# SpaceToDepth first to pack: [1, 10, 30, 30] → [1, 40, 15, 15]
patched = SpaceToDepth(input, blocksize=2)
# Now each "patch" of the original 2x2 region is 4 channels in the smaller tensor.
# Do per-patch ops (which become per-channel on the smaller tensor — cheaper).
# DepthToSpace at the end to restore: [1, 40, 15, 15] → [1, 10, 30, 30]
result = DepthToSpace(patched_op, blocksize=2)
```

**Win**: subsequent ops on `[1, 40, 15, 15]` (~9000 elements) are 4× cheaper than on `[1, 10, 30, 30]` (~9000... actually same element count). The win is when you're doing **per-pixel ops that turn into per-channel ops** — channel ops are often cheaper because of broadcasting.

**2. Upsample without storing a tile pattern:**

Want to replicate each cell to a 3×3 block? Naive: Tile then reshape. With DepthToSpace, generate 9 identical channels (via broadcast or Tile of a small init) then `DepthToSpace(blocksize=3)`. Cost: 1 op vs Tile+Reshape chain.

But beware: 9 identical channels need 9 channels' worth of memory in the intermediate, even if generated by broadcast. Verify the memory accounting.

### Cost

- 0 inits.
- 0 MACs (pure permutation).
- The output tensor has the same number of elements as the input — no element-count change.
- Memory cost: intermediate output tensor only.

### Gotchas

- `blocksize` must divide H and W evenly. For NeuroGolf 30×30: blocksize ∈ {1, 2, 3, 5, 6, 10, 15, 30}.
- For SpaceToDepth, C × blocksize² must be representable. For `blocksize=2` on `[1,10,30,30]`: output `[1, 40, 15, 15]`. Fine.
- `mode` attribute didn't exist before opset 11. Opset 10 graphs always use DCR.

## SpaceToDepth **[opset 1]**

Reverse of DepthToSpace: `[N, C, H·r, W·r]` → `[N, C·r², H, W]`. "Compacts" spatial resolution into channels.

```
SpaceToDepth(input)
attributes:
  blocksize: int (required)
```

No mode attribute — SpaceToDepth has a single canonical layout. Pairs with DepthToSpace DCR mode for round-trip identity.

### NeuroGolf use cases

**1. Reduce spatial dims cheaply:**

Convert `[1, 10, 30, 30]` to `[1, 90, 10, 10]` (blocksize=3). Now per-channel mean/max/sum reductions are on a much smaller spatial extent, but you have 9× more channels (each representing one of the 9 cells in the original 3×3 block).

**2. Pattern detection at fixed period:**

If the spatial pattern is known to repeat at period 5, SpaceToDepth with `blocksize=5` packs each 5×5 tile into 25 channels of a `[1, 250, 6, 6]` tensor. Then you can compare the per-period channel groups against each other to detect rule violations.

### Cost

Same as DepthToSpace: 0 inits, 0 MACs, identical element count.

## Resize **[opset 13 for the modern form]**

Resize spatial dimensions of a tensor with various interpolation modes.

```
Resize(X, roi, scales, sizes)
attributes:
  mode: "nearest" (default) / "linear" / "cubic"
  coordinate_transformation_mode: "half_pixel" (default) / "asymmetric" / "align_corners" / "tf_crop_and_resize" / ...
  nearest_mode: "round_prefer_floor" (default) / "round_prefer_ceil" / "floor" / "ceil"
  cubic_coeff_a: float (only if mode="cubic")
  exclude_outside: int
  extrapolation_value: float
  antialias: int (opset 18+)
  axes: list of ints (opset 18+)
  keep_aspect_ratio_policy: str (opset 18+)
```

Inputs (only one of `scales` or `sizes` should be non-empty):
- `X`: input tensor.
- `roi`: empty unless `coordinate_transformation_mode="tf_crop_and_resize"`.
- `scales`: F32 1-D tensor of per-dim scale factors.
- `sizes`: INT64 1-D tensor of per-dim output sizes.

### The useful subset for NeuroGolf

**`mode="nearest"` + integer scales** = pure replication, very cheap.

```python
# Upsample 15×15 → 30×30 by 2× nearest replication:
scales = numpy_helper.from_array(np.array([1.0, 1.0, 2.0, 2.0], dtype=np.float32), name="up2x")
# Then: Resize(X, roi="", scales)
```

Each pixel becomes a 2×2 block of identical copies. Useful for:
- Upsampling a small-grid template to 30×30 for comparison with input.
- Generating periodic patterns: if the period-3 base is `[5, 5]`, resize to `[15, 15]` gives the pattern with period 3 (each cell appears 3×3 times).

### Downsampling

`scales = [1, 1, 0.5, 0.5]` halves spatial dims with nearest pick. Could replace Slice-with-step patterns.

### Cost analysis

- Init cost: ~32 bytes for scales (4 F32) or sizes (4 INT64).
- 0 MACs (nearest mode).
- For linear/cubic modes, MACs are non-trivial — usually not worth it for color grids.

### Gotchas

- **Many attribute combinations don't compile under all ORT versions.** Stick to `mode="nearest"`, `coordinate_transformation_mode="asymmetric"`, all other attrs default.
- For pure replication, `coordinate_transformation_mode="asymmetric"` + `nearest_mode="floor"` gives the most predictable behavior (no fractional pixel centers).
- `roi` input is required by the spec even if unused — pass an empty initializer.
- **Verify replication semantics before trusting.** Test: does Resize 1→2 of `[[1, 2]]` give `[[1, 1, 2, 2]]` or `[[1, 2, 1, 2]]`? Empirically test.

### Alternative: Tile

For pure replication of every pixel, `Tile` may be cheaper than Resize:
```
Tile([1, 1, 1, 30], repeats=[1, 1, 30, 1])  # broadcast a row to 30 rows
```

Resize wins when you want to replicate in a structured spatial way (each pixel → kxk block) without the index gymnastics.

## ReverseSequence **[opset 10]**

Reverses parts of a sequence axis on a per-batch basis.

```
ReverseSequence(input, sequence_lens)
attributes:
  batch_axis: int (default 1)
  time_axis: int (default 0)
input: rank ≥ 2 tensor
sequence_lens: INT64 1-D tensor of length input.shape[batch_axis]
output: same shape as input
```

For each "batch", reverses the first `sequence_lens[batch_idx]` elements along `time_axis`. The rest are unchanged.

### NeuroGolf use cases

**1. Per-row reversal:**

Reverse each row of `[1, 10, 30, 30]` only up to that row's active extent:

```python
# Treat batch_axis=2 (rows), time_axis=3 (cols)
# sequence_lens = [extent_row0, extent_row1, ..., extent_row29]
ReverseSequence(input, lens, batch_axis=2, time_axis=3)
```

Each row gets reversed up to its own length. Per-row variable-extent reversal in one op.

**2. Diagonal reversal:**

Combined with `Transpose`, can reverse along diagonals.

### Cost

- Init cost: 8 × batch_dim bytes for sequence_lens (INT64).
- 0 MACs (pure permutation).
- 0 added intermediates beyond output.

### Gotchas

- `batch_axis` and `time_axis` defaults are `(1, 0)` — opposite of what you'd intuit for image-style tensors. **Always specify both explicitly.**
- `sequence_lens` is INT64 only.
- For full-length reversal, `Slice` with `steps=[-1]` is simpler (1 op, no init).
- **ReverseSequence wins when per-batch reversal length varies**. For uniform reversal, use Slice.

## Combining: spatial period detection

Suppose you want to detect if an input has period-3 horizontal repetition.

```python
# Method A: SpaceToDepth then compare channel groups
packed = SpaceToDepth(input, blocksize=3)
# packed is [1, 10*9, 10, 10] — each cell is one of the 9 period-3 positions
# Slice out positions [0, 3, 6] vs [1, 4, 7] vs [2, 5, 8] groups and compare

# Method B: Slice + ReverseSequence comparisons
sl_0_27 = Slice(input, [0], [27], axes=[3], steps=[1])   # cols 0..26
sl_3_30 = Slice(input, [3], [30], axes=[3], steps=[1])   # cols 3..29
diff = Sub(sl_0_27, sl_3_30)  # zero if period-3 holds
```

Method A is more elegant for detecting if the pattern is **strictly period-3**. Method B works when you just need a difference signal.
