# task357 (11,082 → 1,312 staged, byte-equal): two reusable moves (2026-06-07)

Context: LIVE memorized 9 full one-hot 10×10 outputs (9,000-param F16 bank) indexed by grid
width. v3 keeps the lookup *shape* but stores only the pattern's PARAMETER, then #67 Equal-tails.

1. **Parameter-LUT beats both the output-LUT and the computed closed form.** When a task's
   output family is generated by a tiny per-index parameter vector (here: ball column per row,
   [9,10,1] u8 = 90 params), storing THAT beats (a) the full output bank (900+ params even as
   u8 color-index) and (b) computing the closed form at runtime — the Mod/Abs triangle-wave
   chain saves 80 params but costs 154 B of int intermediates → net +74. Price the three-way
   crossover (output-LUT / parameter-LUT / computed) before building; the parameter-LUT is
   the sweet spot whenever params(parameter table) < intermediates(arithmetic chain).

2. **A sliced one-hot input row IS a mask — Cast(F32→BOOL), no Less, no iota.** ch0 of an
   all-bg row is 1.0 inside the grid and 0.0 in padding, so `Slice → Cast(BOOL)` yields the
   in-grid (strip) mask for free off the tensor you already sliced for the width count.
   Kills a Less node + the runtime-W comparison vector. Generalizes to any task that reads a
   count via ReduceSum of a one-hot slice: the pre-sum slice doubles as the geometry mask.

Also re-confirmed: negative Gather indices are legal ONNX (zeros-profile W=0 → idx −2 wraps);
useful whenever a bank index is `count − k` and profiling may feed zeros.
