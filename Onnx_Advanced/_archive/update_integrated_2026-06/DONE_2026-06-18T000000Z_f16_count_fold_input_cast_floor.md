## "Fold the F32→F16 Cast into the producing Einsum" is a trap when the producer reads `input`

**What I discovered (task093, worker-093):** A common-looking micro-opt — "the Einsum emits an F32 `[1,30]` count that is immediately `Cast`→F16, so just make the Einsum emit F16 directly" — is a hard regression whenever the Einsum's collapsing operand is the network `input`. ORT Einsum has no mixed-dtype kernel, so an F16 output requires ALL operands F16, including `input`. `input` itself is a scorer-free graph tensor, but `Cast(input)->F16` is NOT free — it materializes a full `[1,10,30,30]` F16 plane (18,000 B). On task093 that turned the team-best 1715 graph into 19,229 (memory 18,988), while still passing visible 265/265 (so the fold is logically correct — cost is the only killer).

**The accounting law:** Casting a tiny F32 intermediate to F16 to delete its F32 carrier only wins if the F32 source you replace is itself small. Here the would-be source is `input` (free), and the cast's output is the full plane. The four F32 count carriers cost only 480 B total; the cheapest pre-collapse you could cast instead (`[1,30,30]` F16 = 1,800 B) already loses to them. So **F32-count-Einsum → Cast-to-F16-`[1,30]` (720 B for 4 counts) IS the floor** for producing narrow F16 vectors from an F32 one-hot input — do not try to fold the cast into the Einsum.

**Already in the library, just connect them:** `techniques.md` §89 caveat ("all Einsum operands must share the input dtype … you cannot F16 the vectors without casting the whole input to an 18 KB F16 plane") and §91 dtype-floor ("F16 multi-operand einsum is NOT byte-equal, task191") state the dtype rule. What's missing is the explicit *cost* corollary: **a Cast that narrows a charged tensor pays for the cast's own output bytes; narrowing `input` is therefore anti-economical because input is otherwise free.** The prompt-suggested "Cast(input)->F16 once up front deletes the carriers" framing is the exact false-economy this note refutes.

**Evidence:** prototype `The_400_Tasks/Task_by_Task/task093/prototypes/task093_inputcast_f16.onnx` (built via inline script; visible 265/265, score memory 18,988 + params 241 = 19,229). Team-best floor `staged_submits/task093_signed_reuse_halves_castbool_cost1715/task093.onnx` unchanged at 1715.
