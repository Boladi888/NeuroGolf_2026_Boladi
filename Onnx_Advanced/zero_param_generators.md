# zero_param_generators.md — ops that produce tensors WITHOUT initializer cost

The cheapest initializer is the one you don't store. These ops generate tensors at runtime from attributes / scalar inputs, contributing **zero `params`** (or near-zero) to the score.

For a NeuroGolf graph where every 900-element BOOL mask costs 900 params, this is often the difference between shipping and not.

**Scorer caveat (task215/task007): zero initializer cost is not zero memory.** If the generated tensor
survives as a graph intermediate, `calculate_memory` charges its output bytes. `Tile`, `Range`,
`Gather`, and `ConstantOfShape` only win when they replace a dense initializer without creating a larger
runtime tensor, feed directly into the graph output, or are absorbed inside a free-output contraction.
Always profile the rewrite; all-init does not guarantee folded-away.

## Trilu — triangular mask **[opset 14]**

Generates upper- or lower-triangular form of an input tensor.

```
Trilu(input, k=0)
attributes:
  upper: int (default 1) — 1 = upper triangle, 0 = lower
```

Output shape = input shape. Elements outside the triangle are set to 0; inside are preserved.

### The zero-init trick

Feed `Trilu` an input that's already a constant of all-ones generated by `ConstantOfShape`. The whole triangular mask costs **2 scalar inits** (shape + fill value), regardless of size:

```python
# 30×30 lower-triangular BOOL mask — ZERO data inits
shape_init = numpy_helper.from_array(np.array([30, 30], dtype=np.int64), name="shape_30x30")
# ConstantOfShape with no `value` attribute defaults to F32 zeros
ones = ConstantOfShape(shape_init, value=Tensor(np.array([True], dtype=np.bool_)))
tri = Trilu(ones, k_init_zero, upper=0)
# tri is a [30,30] BOOL lower-triangular mask. Total init cost: shape (2 INT64) + value (1 BOOL) = 17 bytes
```

vs. the naive approach:
```python
tri = np.tril(np.ones((30, 30), dtype=np.bool_))   # 900-byte BOOL init
```

**Savings: 883 bytes per triangular mask.**

### Diagonal-offset variant

`k` is the second input (INT64 scalar). `k=0` is the main diagonal. `k=1` shifts the boundary one step upward (so for `upper=1`, the diagonal becomes part of the zeroed region instead of the kept region). `k=-1` shifts downward.

[ASSUMED] convention matches `np.triu(arr, k)` / `np.tril(arr, k)`.

### NeuroGolf use cases

- Per-task lower-triangular accumulator masks for "fill from this cell down-right" patterns.
- Reflected/rotated triangle patterns (combine with `Transpose` or `Slice` negstep — NOT `ReverseSequence`, which is validator-banned; substring "Sequence", see ort_reality.md banned ops).
- Diagonal bands (compute `Trilu(ones, k=1) - Trilu(ones, k=-2)` to get a 4-wide diagonal band — still under 30 init bytes).

### Gotchas

- **RESOLVED (N3 source-read of ORT v1.24.4 `trilu.cc`, 2026-06-19): Trilu CPU dtypes = bool/f32/f64/i64 — BOOL input WORKS; UINT8 does NOT (no kernel).** The all-ones-BOOL trick above is safe; for a u8 triangle, build bool then `Cast`.
- Opset 14 — many NeuroGolf submissions target opset 10–13. Bump opset_import to 14 first.
- `k` is an input tensor, not an attribute. INT64 scalar.

## EyeLike — identity-like tensor **[opset 9]**

Generates a 2-D tensor with ones on a diagonal and zeros elsewhere. Shape matches input.

```
EyeLike(input)
attributes:
  dtype: int (default = input dtype) — TensorProto enum
  k: int (default 0) — diagonal offset
```

Like `np.eye(N, k=k)` but the size is taken from the input's shape.

### The zero-init trick

Feed it a `ConstantOfShape`-generated `[N, N]` tensor:

```python
shape_NN = numpy_helper.from_array(np.array([30, 30], dtype=np.int64), name="shape_NN")
zeros = ConstantOfShape(shape_NN)  # F32 zeros, default
identity = EyeLike(zeros, dtype=TensorProto.INT32, k=0)  # ⚠ NOT BOOL/UINT8 — no ORT CPU kernel (see gotchas)
# 30×30 INT32 identity. Total init: 2 INT64 = 16 bytes vs 900 bytes for stored mask.
# For a BOOL diagonal, skip EyeLike entirely: Equal(iota_row, iota_col) — see Combining patterns below.
```

### NeuroGolf use cases

- Diagonal-only mask without the 30 stored bytes.
- Off-diagonal (`k=1`, `k=-1`, etc.) for "cells immediately above/below diagonal" patterns.
- Combined with `Trilu(EyeLike(...), upper=...)` for diagonal-and-above masks.

### Gotchas

- Input MUST be rank-2. For 4D NeuroGolf tensors, generate the 2D identity first, then Unsqueeze + broadcast.
- `dtype` attribute is TensorProto enum int (9 for BOOL, 6 for INT32, etc.).
- **ORT CPU dtypes (N3 source-read of `eye_like.cc`, 2026-06-19): f32/f64/i32/i64/u64 — NO bool/u8.** `EyeLike(BOOL)`/`EyeLike(UINT8)` have no kernel and fail to run. For a bool diagonal use `Equal(iota_row, iota_col)`; for numeric, `EyeLike(INT32)` then `Cast` if bool is needed.

## Range — arithmetic progression **[opset 11]**

Generates `[start, start+delta, start+2*delta, ..., limit)` (exclusive on `limit`).

```
Range(start, limit, delta)
all three are scalar tensors (shape [])
output: 1-D tensor
```

### Cost analysis — **CORRECTED 2026-06-06 (task055 probe): Range LOSES under the current scorer**

The old analysis below only priced the inits and assumed the Range OUTPUT was free.
**It is not**: `calculate_memory` charges Range's output like any intermediate
([30] INT64 = 240 B). Measured twin probes (task055): init-iota graph scored
memory 150 / params 31 (= 181); range-iota graph scored memory **390** / params 4
(= 394). **An `np.arange(N)` initializer costs N params; Range costs
N×itemsize BYTES + 3 params — the init wins for every dtype at every N**
(params count elements, so the init is dtype-independent: arange(30) = 30 cost
vs Range-I64 = 243). Use Range ONLY if a downstream op requires a runtime tensor
that shape-inference cannot see... which the validator rejects anyway.

~~Stored as 3 scalar inits: F32 12 bytes / INT64 24 bytes total vs arange N×itemsize.
Break-even at N≥3. Range almost always wins.~~  ← WRONG: ignored the charged output.

### NeuroGolf use cases

- ~~`range30` as INT64 indices: Range = 24 bytes vs arange = 240 bytes~~ **WRONG —
  see correction above; arange-init = 30 params beats Range = 240 B + 3 params.**
- Multiple Range outputs from different (start, limit, delta) triples can share the type-promoted constants — combine with CSE.
- Position-aware computations: `Range(0, 30, 1)` then `Mul(positions, ...)` for per-position weights.

### Gotchas

- All 3 inputs must be same dtype.
- Dtype constraint: F32, F64, INT16, INT32, INT64. **No BOOL, UINT8.**
- For UINT8 ranges, generate INT32 then `Cast(INT32→UINT8)`. Net positive only if multiple downstream uses share the Cast.
- `limit` is EXCLUSIVE. `Range(0, 30, 1)` gives 30 elements [0..29].

## ConstantOfShape — fill tensor with one value **[opset 9]**

Generates a tensor of arbitrary shape filled with one value.

```
ConstantOfShape(shape)
attributes:
  value: TensorProto (1-element, optional; default = F32 0.0)
shape: INT64 1-D tensor (the desired output shape)
output: tensor of the specified shape, filled with `value`
```

### Cost analysis

Two inits:
- `shape`: rank elements × 8 bytes (INT64). For 4D NeuroGolf: 32 bytes.
- `value`: 1 element × dtype bytes. For BOOL: 1 byte. For F32: 4 bytes.

**Total: ~33 bytes for a constant-fill tensor of any size.**

vs. `np.full((1, 10, 30, 30), 1.0)` stored as init: 36,000 bytes (F32) or 9,000 bytes (BOOL).

**Savings: ~35,967 bytes for a full-graph-shape constant fill.**

For NeuroGolf `cost`, those are param/file-byte savings, not a blanket memory saving. A generated
`[1,10,30,30]` BOOL tensor that is consumed by another node is still a 9,000 B memory intermediate.
Use `ConstantOfShape` for uniform-fill initializers, direct outputs, or inputs to a free-output op; do
not insert it as a "free" replacement for a charged runtime plane.

### NeuroGolf use cases (beyond the obvious)

- Generate the input to `Trilu` or `EyeLike` for triangular/identity masks (above).
- Per-channel constant masks: `ConstantOfShape([1, 1, 1, 30], value=True)` for a 30-wide row mask that broadcasts across all channels.
- All-zeros tensor for `Where(condition, x, all_zeros)` — no need to store the zeros.
- All-ones tensor for `Mul(..., ones)` identity (though this is wasteful — drop the Mul instead).
- F16 scalar constants: smaller than F32 (`value` is 2 bytes vs 4).

### Gotchas

- `value` attribute is a TensorProto, not a scalar literal. Construct via `helper.make_tensor("v", TensorProto.BOOL, [1], [True])` then pass via `value=...`.
- The `shape` input is RUNTIME — could come from another op's output, enabling **dynamic shapes**. For static graphs, just use an init.
- Default `value` is F32 0.0 — if you forget the attribute and your downstream expects BOOL, you'll get a dtype mismatch.

## Combining patterns

### Zero-init `[1, 10, 30, 30]` all-ones BOOL tensor

```python
shape = numpy_helper.from_array(np.array([1, 10, 30, 30], dtype=np.int64), name="full_shape")
one_bool = helper.make_tensor("one_bool", TensorProto.BOOL, [1], [True])
# In graph:
all_ones = ConstantOfShape(shape, value=one_bool)
# Total: 32 bytes (shape) + 1 byte (value) = 33 bytes
# vs np.ones((1,10,30,30), dtype=np.bool_) = 9000 bytes
```

### Zero-init diagonal mask broadcast across channels

```python
# BOOL diagonal WITHOUT EyeLike (no bool/u8 CPU kernel): compare two iotas.
iota = numpy_helper.from_array(np.arange(30, dtype=np.int64), name="iota30")  # 30 params
row = Reshape(iota, [30, 1]); col = Reshape(iota, [1, 30])
diag_2d = Equal(row, col)                       # [30, 30] BOOL diagonal
diag_4d = Unsqueeze(Unsqueeze(diag_2d, axes_0), axes_0)
# Broadcasts against [1, 10, 30, 30] for free. (Need numeric? EyeLike(zeros_2d, dtype=INT32) then Cast.)
```

### Banded mask (between diagonals k and -k)

```python
# Width-2 diagonal band: upper triangle of (-1, +1)
upper = Trilu(all_ones_2d, k_init_1, upper=1)
lower = Trilu(all_ones_2d, k_init_neg_1, upper=0)
band = And(upper, lower)
# 4 nodes + ~30 init bytes for a 30x30 band mask. vs ~900 stored.
```

## RESOLVED (N3/R6, 2026-06-19) — formerly "verify empirically"

1. **`Trilu` at opset 14 loads** (basic kernel). CPU dtypes = bool/f32/f64/i64; **no u8**.
2. **`EyeLike` does NOT accept bool/u8 output on ORT CPU** (kernels f32/f64/i32/i64/u64 — source-read of `eye_like.cc`). `Trilu` DOES accept bool (not u8). Bool diagonal → `Equal(iota,iota)`; bool triangle → `Trilu(bool_ones)`.
3. **None of these are banned** — `Trilu`/`EyeLike`/`Range`/`ConstantOfShape` are clean. (The validator bans LOOP/SCAN/NONZERO/UNIQUE/SCRIPT/FUNCTION/COMPRESS + any op whose name contains the substring "Sequence"; `ReverseSequence` IS therefore banned.)
4. MAC cost ≈ 0 (shape-only / generation ops). The live cost is the charged OUTPUT bytes if the generated tensor survives as an intermediate — see the scorer caveat at the top of this file.
