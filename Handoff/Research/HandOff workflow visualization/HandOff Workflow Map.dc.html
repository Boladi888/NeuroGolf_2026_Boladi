The vocabulary — what actually exists in the workflow
Two stacks. HandOff-native objects are the shared record — anyone on the project can see them. Local NG automation is private to this machine. Most confusion is a gap between the two: work happens locally but never becomes a native object. Click any card for detail.
HANDOFF-NATIVE OBJECTSshared · visible to the requester
ProjectNG uses one
Top container: one body of work with its own team, board and files — NeuroGolf_HO.
Goalbatch = goal
A milestone / grouping under a project. NG maps one prompt batch to one goal.
Taskthe atom
The unit you assign, track and verify. Has status, assignee, messages, files.
Assignee / agentholds the key
The agent that owns a task and holds the key to move its status.
Status / eventshared lifecycle
Canonical status + event stream — the shared heartbeat of progress.
Message / commentnarrative
Human-readable notes on a task — the cheapest record of what happened.
File shareshared files
Files attached to the shared record so anyone on the project can retrieve them.
Artifactevidence
Any output made while working — often intermediate. Proof work happened.
Deliverableaccepted · final
The finished, accepted output meant to be handed over. HandOff supports this; NG needs to publish to it.
Proposalpending approval
A suggested change submitted for approval before acting.

Drives worker / reviewer sessions; claims and should update tasks.

The scarce submit / release gate to the team.

Heartbeat / presenceonline
Keeps an agent "online" so absence is detectable.

Rule of thumb — new PROJECT vs GOAL vs TASK. New project only for a different team / permission boundary or a long-lived separate initiative. A goal is a batch or milestone inside NG. A task is one unit of work. When in doubt, prefer a goal / task under NeuroGolf_HO — a new project fragments visibility and permissions.

Where confusion actually happens
Six real questions this workflow keeps raising. The pattern behind all of them: local truth is richer than the board, and nothing forces the two to reconcile. Each card says how to tell.
“Did the agent actually do anything?”
Board status can sit at todo while a worker runs for hours locally — the runner doesn’t post back.
WHAT THIS MEANS · board silence ≠ no work
TELL BY → runner logs + heartbeat + task messages, not the board column alone
“Where did the output land?”
Results are written to local Updates_* inboxes and staged files — not uploaded to the task.
WHAT THIS MEANS · the task looks empty; the output is real but off-board
TELL BY → captain inbox / manifest.csv locally; ideally a deliverable linked on the task
“Which status actually matters?”
The board has 5 canonical statuses; the runner tracks SHIP / HELD / PROBING / … on top.
WHAT THIS MEANS · board = shared truth; local substates = richer but private
TELL BY → for coordination trust the board; for detail open the task’s substate
“Is this live or stale?”
A file timestamp or an “online” badge doesn’t prove a process is alive.
WHAT THIS MEANS · fresh-looking ≠ running
TELL BY → monitor state_age + pid liveness + last heartbeat < poll interval
“Deliverable, or just an artifact?”
Both are files in a folder; nothing marks which one is the accepted hand-over.
WHAT THIS MEANS · not every artifact is meant to be consumed
TELL BY → only a reviewer-verified, explicitly-marked output is a deliverable
“New project, or a goal / task?”
It’s tempting to spin a new project per batch or experiment.
WHAT THIS MEANS · new projects fragment visibility and permissions
TELL BY → new project only for a different team / boundary; else a goal / task under NeuroGolf_HO

The runner tracks richer substates than the board can hold, so worker_running lingers as board todo and review_running hides inside pending_verification. Click the red DRIFT bar for the full state map — then switch to Optimized to see the fix.
Next bridge to build: worker/reviewer/captain events should update the task, attach artifacts, and publish accepted SHIP output as a HandOff deliverable. Local files can remain the execution truth; the task should become the audit truth.
