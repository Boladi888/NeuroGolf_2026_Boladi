# Task_by_Task/

One `.md` per task (`task000.md` ... `task400.md`, **401 files**). Source of truth for the per-task working notes that aren't easily captured in the structured columns of `task_state.csv` / `NeuroGolf_Task_Status.xlsx`.

**Audience:** AI agents only. Technical, terse, no fancy formatting.

## What goes in each .md

1. **Rule** — 1-3 sentences on the transformation. "unknown" if not derived.
2. **Algorithm sketch** — numpy pseudocode if known, or a pointer to `Research_Archive/notes/recipe-taskNNN-*.md`.
3. **Attempts** — one row per attempt: date, approach, result, cost, session log.
4. **Cost analysis** — why the current cost is what it is, dominant ops, ideas for reducing.
5. **Don't-do log** — ruled-out hypotheses so future agents don't retry them.

**Do NOT** duplicate columns from `task_state.csv` / `NeuroGolf_Task_Status.xlsx` (family, status, cost, etc.). The `.md` is for content the structured columns can't hold — algorithm sketches, attempts history, prose analysis.

## Auto-generation

Each file has a `<!-- AUTO:BEGIN -->` ... `<!-- AUTO:END -->` block that's regenerated by `tools/generate_task_mds.py`. It contains:

- Pointer to the structured row in the xlsx / csv.
- Auto-detected research and prototype links (any `Research_Archive/notes/*-taskNNN-*.md` or `Research_Archive/organic_prototypes/taskNNN_*.py`).

**Manual edits go OUTSIDE the AUTO block.** Re-running the generator preserves manual content.

```bash
python tools/generate_task_mds.py
```

## Why a flat folder (no subfolders)?

The `family` column in `task_state.csv` does the categorization. Subfolders would lock the categorization into the filesystem and break it whenever a task's family changes. A flat folder + `family` column is easier to re-bucket.

To list all tasks in a family during a per-family session:

```bash
python -c "
import csv
fam = 'Pattern_Recognition'
with open('The_400_Tasks/task_state.csv') as f:
    for r in csv.DictReader(f):
        if r['family'] == fam:
            print(r['task'])
"
```
