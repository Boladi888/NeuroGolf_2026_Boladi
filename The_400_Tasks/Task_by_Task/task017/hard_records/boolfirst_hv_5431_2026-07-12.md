## Forced-floor argument — bool-first CANNOT reach 3963
- **Fill is shared & forced:** P (F32 [1,9,30]=1080) + Pb 270 + q 60 = 1410. The residue one-hot MUST be
  F32 to Einsum with the F32 `input`; a Gather-based fill is data-dependent (which class member holds the
  color depends on hole positions) → dynamic/unsafe; the index-plane fill is the staged **4992** route
  (proven worse). So the fill tail ≈ Sho's.
- **Detector needs ≥ one 21×21 F32 plane = 1764.** The foreground/background indicator requires isolating
  channel 0 (or 1..9); the cheapest is `Slice(input, ch0, :21,:21)` = 1764. There is NO single op that
  produces a bool/U8 21×21 mask from F32 `input` (Einsum/Conv output dtype follows F32 input; a channel
  collapse via ReduceMax is [1,1,30,30] F32 = 3600, even worse). So a "bool mask" still costs a **1764 F32
  plane** — same as Sho's D; the "keep masks bool" premise yields no plane saving.
- **The both-present count needs a SECOND resource:** either a 2nd plane fg21 (+1764, the built version →
  5431) or prefix-sum machinery over bg (+~600 mem +~40 params, one-plane version).
- Forced essentials (one-plane best case) = bg21 1764 + P 1080 + Pb 270 + q 60 = **3174**, leaving **<789**
  for a detector that minimally needs ~900 (separate H+V autocorr + both-present + selection) → **≈4074 > 3963.**
- Sho spends 510 params on the rank-5 D factorization to buy **single-plane** efficiency; his 2G−dd==21(21−p)
  test needs only D's self-Conv + input's self-Conv (2 autocorrs). Bool-first saves those 510 params but pays
  more in a 2nd plane / H+V detector tensors. **Net worse.**
