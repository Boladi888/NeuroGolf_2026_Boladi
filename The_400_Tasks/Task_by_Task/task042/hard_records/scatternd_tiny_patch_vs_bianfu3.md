# ScatterND tiny-patch price wall vs Sho bianfu3

- **Live bar when recorded:** manifest/profile cost **1813**, SHA `cdfd71e0fbef2fde3f7b44be3668817c16aae450cb19219e0cf6ee02497c5b15`, source `python tools/ng_current_bar.py --task 42 --json` / `Team_Best_Onnx/task042.onnx`, owner Sho, updated `2026-07-09T01:09:17Z`.
- **Attempted route:** replace the bianfu3 free-output QLinearConv render with a ScatterND tiny-patch writer over the F32 `input` base. Prompt route was plausible against the older 2322/2522 Where-tail graphs, but the live graph already avoids the 900 B full-canvas Where mask and writes the final `[1,10,30,30]` output as the last QLinearConv.
- **Failed gate / price probe:** killed before ONNX build. A correct dynamic ScatterND needs a fixed max update bank for n=3: two 3x3 cyan blocks plus channel-0 clears = up to **36 writes**. Runtime dynamic indices are at least `[36,4] INT64 = 1152 B`; selecting an offset bank and then adding the runtime anchor forces at least two such charged tensors (**2304 B**) before the green-cell read, anchor/moment derivation, update values, and ScatterND itself. That already exceeds the 1813 live bar.
- **Why dead:** ScatterND only wins when sparse indices are static or the runtime base vector is already paid. Here the task's hard part is computing orientation/scale/anchor and materializing the dynamic multi-channel index bank. Reusing the F32 input as ScatterND data also locks updates to F32. The current bianfu3 graph's charged memory is only **1385 B** total and its final full output is free, so the ScatterND index bank alone is too expensive.
- **One remaining hypothesis:** a ScatterND route would need a zero-cost or scalar-only way to make the `[36,4]` index tensor the direct ScatterND input without a separate selected-offset materialization. No known ONNX op provides that; if a future model already has the exact target index bank as a byproduct, reprice then.
