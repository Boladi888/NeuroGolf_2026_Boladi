## FREE-OUTPUT WALL — why FreeoutStampEinsum (#132/#118/#119) cannot beat the Where-family (worker-033-1, 2026-06-20)

The folder-8 prompt's lever is to dissolve the 900B `Where` condition into a free-output stamp Einsum. **It fails for this rule, by structure, not by tuning** — measured 6,283 (Einsum-expand) and 139,480 (full additive-logit reconstruction):

1. **The paint plane is rank>1 AND data-dependent.** `paint[h,w] = tiled_motif[h,w] ∧ is_empty[h,w]`. The per-cell empty guard reads 81 scattered F32 cells (#145 floor, 324B). The joint (motif ∧ guard) is a full 9×9 logical matrix `P9[i,j]` placed by bases — a **bilinear form** `Br[i,h]·P9[i,j]·Bc[j,w]`, NOT a rank-1 outer product. The #109/#119 separable free-output requires every term to be rank-1; a rank>1 plane must materialize as a real [30,30] tensor (≥900B BOOL via Gather-tiling, or 3,600B F32 via Einsum). The cheapest materialization IS the current BOOL Gather route (`fill30`).
2. **Routing a plane to data-dependent channels is F32-locked and explodes.** `e_lc`/`e_oc` are data-dependent one-hot channel selectors. Multiplying a [30,30] plane by an `[1,10,1,1]` selector yields a charged `[1,10,30,30]` **F32** margin = 9,000B — vs `Where(cond[1,1,30,30], line_color, input)` which routes the plane to channels for FREE (Where output uncharged) AND preserves the input (objects+lines+bg) for FREE in the else-branch.
3. **Input preservation is free only via `Where`'s else-branch.** Reconstructing objects/lines/background separably is impossible (object placements are arbitrary, data-dependent), so any no-Where reconstruction must rebuild them as charged F32 planes. `Where`-as-output is the structurally cheapest input-preserving final op — confirming the original floor-proof conclusion against the new lever.

**Net:** the FreeoutStampEinsum twin of #129 helps when the stamp output is data-INDEPENDENT and rank-K separable (task327). task033's paint requires a per-cell data-dependent guard ∧ a rank>1 motif placed to data-dependent channels — three independent reasons the free output cannot stay separable. The `Where(fill30, line_color, input)` family at **2256** (profile==static==2256, arcgen 266, w-033-1 2026-06-20) remains the tightest formulation we can build; an exact byte re-derivation of the leanest possible Where graph reproduces 2256 to the byte. **This does NOT prove 2256 is THE task floor** — Aditya holds 1639, a family we cannot read or reconstruct from available info; treat 1639 as an unbeaten target via an unknown formulation, not as a proven wall.

## Rule

ARC-GEN UUID `1e32b0e9` (`external/ARC-GEN/tasks/task_1e32b0e9.py`).
The grid is always a 17×17 `hollywood_squares(3, size=5)` layout: three 5×5 cells per axis, separated by line rows/cols. The top-left cell contains the complete 3×3-interior shape. Output copies that top-left shape into every 5×5 cell, painting missing shape pixels with `linecolor`, while preserving any existing object-color pixels.

## Algorithm sketch

```python
linecolor = input[5][0]
shape = {(r, c) for r in 1..3 for c in 1..3 if input[r][c] != 0}
out = copy(input)
for mr in range(3):
    for mc in range(3):
        for r, c in shape:
            rr = mr * 6 + r
            cc = mc * 6 + c
            if out[rr][cc] == 0:
                out[rr][cc] = linecolor
```

ONNX winning formulation: read only the 9×9 candidate interior cells' ch0 values with `GatherND`, compute the repeated shape/background fill mask in BOOL, expand it directly to 30×30 through a sentinel `Gather`, then use final `Where(fill30, line_color, input)` as the free output node.

## FLOOR PROOF — 2,256 is the structural floor of the `Where`-as-output family (w-C1 2026-06-11)

Exact rank3 cost decomposition (`score_v2` + shape-inference per-tensor):

| tensor | bytes | forced? | why |
|---|---:|---|---|
| `fill30` `[1,30,30]` BOOL | 900 | YES | the `Where(cond, line, input)` condition must be broadcastable to `[1,10,30,30]`; a 17×17 cond cannot broadcast (`bool_crop17` padded it back and cost **3,206**). |
| `bg9_f32` `[1,9,9]` F32 | 324 | YES | the background guard needs all 81 candidate interior cells (shape varies per instance → can't pre-prune statically). Reading 81 F32 values = 324 B. |
| `idx_bg9` `[1,9,9,3]` INT64 | 243 (params) | YES | the GatherND index that reads exactly those 81 scattered points **without materializing a plane**. Every alternative is worse (below). |
| `fill_rows` `[1,30,10]` BOOL | 300 | YES | one-axis 9→30 expansion intermediate; symmetric col-first gives `[1,10,30]`=300 — no asymmetric win. |
| `fill10`/`bg9`/`template9`/`fill9` | 100+81+81+81 | YES | pad-to-10 false sentinel + BOOL template tile/AND chain; BOOL (1 B) is already the cheapest dtype. |
| `line_color`+`template_rows`+indices | ~137 | YES | `Where` value arg + separable 3→9 tile scratch + small index inits. |

**`idx_bg9` (243) cannot be shrunk** — three independent dead-ends, all measured:
1. **Pre-slice channel** to allow a 2-element `[r,c]` GatherND index (162): requires a squeezed `[1,30,30]` F32 ch0 plane = **3,600 B** intermediate. Net loss.
2. **Separable row-then-col read** (`row_idx`=18): GatherND reads 9 full-width rows → `bg_rows_f32` `[1,9,30]`=**1,080 F32**. `bool_sparse9_rowgather` measured **3,066**.
3. **Runtime-generate the index** (Range/Tile/Concat, 0 params): the assembled `[1,9,9,3]` INT64 intermediate = 243×8 = **1,944 B**. Far worse than the 243-element initializer (params count elements, not bytes; INT64 init = 243).
   GatherND's 81-point sparse F32 read (324) is provably optimal vs any plane-materializing or index-generating alternative over an F32 `[1,10,30,30]` input.

**Separable row/col bases (the prompt's hypothesis) are ruled out by the RULE, not just cost**: the top-left 3×3 template is an arbitrary shape (e.g. the plus `020/222/020` in train[0]) — **rank>1, not an outer product**. A row-base × col-base reconstruction can only express rank-1 (axis-aligned-rectangle) templates, so it would silently fail non-separable shapes (same failure class as `gencontract`). The 9×9 template AND-chain is forced.

**Sub-900 is impossible without abandoning `Where`-as-output**, and no input-identity-preserving final op exists that avoids a full `[*,30,30]` condition plane (ScatterND dynamic-update path priced worse in the original analysis). **Verdict: 2,256 = floor for this family.** No candidate < 2,256 staged (per protocol; do not stage ≥ team-best).
