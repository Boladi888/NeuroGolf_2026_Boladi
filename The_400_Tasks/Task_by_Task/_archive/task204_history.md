## 2026-05-31 v1 dead ends
- Do not replace exact ring equality with "spread raw ring counts then threshold": on 500 ARC-GEN samples, false projected scores exceeded true scores (even false max 1180 vs true min 38; odd false max 862 vs true min 23).
- Do not use horizontal gap fill alone: it matched only 384/5000 fresh ARC-GEN samples because rows shared by multiple boxes create false bounded gaps. Any row-gap rewrite needs a vertical/square gate.
- Sparse QLinearConv weights are not currently scoreable through the official sanitize path: ORT can load a sparse-weight probe, but `score_network_v2` returns `None` because sanitize renames node inputs without renaming sparse initializers / QLinearConv shape inference rejects sparse tensor inputs.
- Nearest row+column boundedness is close but not exact: nearest left/right/up/down with equal spans matched 4953/5000 ARC-GEN; adding corner checks improved to 4994/5000 but still false-filled cells where different boxes formed accidental corners. A row/column rewrite needs full edge validation, which is essentially the ring detector again.
- Do not chase opset-10 Pad-attribute savings on v2: Pad attributes would remove only the 8-element pads initializer, and downgrading the graph to opset 10 makes the `UINT8` `Max` nodes invalid under ORT/scorer.
- Do not expect a simple low-rank detector-channel collapse in the current anchor-paint architecture: the 8 length-specific 10x10 paint matrices have numerical rank 8 for full color, full support, interior-only support, and interior-only final color. Fewer linear anchor channels therefore need a later nonlinear decode that re-materializes equivalent length masks.
- MaxPool prefix/suffix scans from `Onnx_Advanced/by_symptom.md` are useful for rectangle blockers, but not a clear win here: exact top-edge length, above/left/after-edge suppression, and length-specific paint are already fused in one sparse signed `QLinearConv`; the MaxPool version needs separate per-length blocker maps and loses the parameter savings to extra activations.
- The `Where(fill_mask, overlay, input)` output-overlay trick is not cheaper for v2. It avoids rebuilding unchanged blue/background in principle, but the red/orange overlay still has to become a `[1,10,30,30]` branch before `Where` (or it needs full input color-code slices), so the 9k one-hot/Where branch costs far more than the current 900-byte label-code pad plus final graph-output `Equal`.
- Do not unify the v2 quantized chain to all-`INT8` just to share a zero point: a direct probe kept the same score `(0,6652,1030)` and diverged from live on 117/268 pairs because the signed paint path changes quantization semantics.
- Different-architecture probe, directional nearest-boundary fill: a NumPy solver using nearest blue left/right/up/down plus full edge-continuity checks hit 3000/3000 fresh ARC-GEN. A cheaper local-edge-only variant hit 2999/3000 and false-filled an accidental rectangle framed by unrelated square edges. The exact version is not attractive to encode: it needs nearest-blue and nearest-nonblue distance/run evidence in four directions, which means either many shifted masks, INT64 lookup casts from bitmasks, or bitwise lowbit plumbing plus dynamic edge-run sampling. The mandatory distance-decode intermediates exceed the current 2592-byte v2 detector before output assembly starts.
- Different-architecture probe, direct per-cell learned linear kernels: `SGDClassifier`/hinge probes on 19x19 blue patches for red/orange interiors were not close to separable (500 fresh examples produced thousands of false positives and hundreds of false negatives per color). This confirms the earlier raw-ring-score warning: a direct linear per-cell detector needs an exact template bank, which collapses back toward v1/v2.
- Different-architecture probe, scalar bit-coded anchor plus universal stamp: a single-channel top-left detector can in principle encode length as a power-of-two prefix sum, but painting from that packed code is blocked. Convolution sums overlapping max-10 footprints before relative-offset bitmasks can be applied; short-square overpaint overlaps neighboring boxes despite the generator's 1-cell clearance. An idealized OR-accumulation version and min/max/odd-first/even-first conflict policies all failed immediately on fresh ARC-GEN samples due cross-talk between one square's length code and another square's offset mask. Recovering exact footprints requires unpacking the 8 length channels again.
- Different-architecture probe, modular packed anchors: powers-of-two length codes plus offset-threshold weights can make outside-footprint contributions vanish modulo 256, so the idea can encode exact support in principle with `ConvInteger -> Mod`. It is not cheaper here: direct parity residues are ambiguous across `(length, offset)` pairs, and splitting even/odd needs two INT32 20x20 paint maps plus modulo/threshold maps, which spends more intermediate memory than the 8-channel UINT8 v2 detector saves.
- Full-rewrite probe, horizontal/vertical bracket classifier: aggregate parity-only row/column evidence failed almost every generated sample, and exact length-specific row/column brackets false-filled accidental rectangles unless full edge continuity was reintroduced. The exact version needs per-length identity or nearest-boundary/run evidence, so it does not beat v2's compact top-left length bank.
- Full-rewrite probe, lengthless top-left anchors plus right/bottom border stop: an idealized per-anchor loop was close but still false-filled when another box supplied a matching border. Adding same-anchor top/left continuity fixed common cases but still failed when unrelated aligned edges supplied the continuity. The ONNX form would need offset-specific edge-continuity gates, which is larger than carrying the 8 length channels.
- Full-rewrite probe, top-left/bottom-right corner pairing: nearest or same-delta corner policies failed within the first few thousand ARC-GEN cases because diagonally separated boxes create plausible false rectangles. Full four-edge validation collapses back to the expensive directional-continuity solver.
- Scorer/output hiding is closed: `calculate_memory` rejects `len(graph.output)>1` and `run_network` hard-codes `session.run(["output"], ...)`, so the large detector tensor cannot be hidden as an auxiliary graph output.
