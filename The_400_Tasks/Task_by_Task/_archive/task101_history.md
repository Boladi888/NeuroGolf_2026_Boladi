## Original cost analysis (cost 65,875 era and the compression passes)

Cost 65,875 (memory=54,322, params=11,553). Model already F16 (fp16_selective errors). Params dominated by: v0[1800] MatMul weight, v2[6384=266×24 f16 lookup table], v3[1196=26×46 f16 lookup], v5[900 zeros], v9[900 zeros].

**Crop-to-17×21 analysis** (advisory estimate -21720B): Flattened [1,1800] → [1,714] saves 4344B. Input/output channels shrink saving 26064B total. But adding input_cropped[1,10,17,21]=14280B + output_small[1,10,17,21]=14280B = 28560B overhead. Net: +2496B memory increase, -2164 params. Total cost INCREASES by ~332B. Do not attempt.

**No-Pad approach**: not viable — the previous attempt to remove the final Pad on task170 caused -13.68 LB regression (wrong output shape for hidden scoring).

**2026-05-23 sub-6k compression pass**: best exact live-equivalent ONNX candidate is now `task101_unified_active20.onnx` at cost 5,685 (memory 3,424 + params 2,261). The winning lookup route uses a 46-probe score, a displaced perfect hash (`score % 64`, `(score // 64 + disp[bucket]) % 280`) to gather metadata directly, triple-packed active fill positions, and a 17×20 BOOL scatter mask padded to the 30×30 output mask. Still above the sub-5k/sub-3k stretch targets. Tested dead ends: sparse initializer for `mask_zero` (checker rejects sparse bool for `ScatterElements`), direct `ArgMax` on BOOL (ORT rejects BOOL `ArgMax`), int8/int16 `TopK` (ORT unsupported), removing the safe-index `Where` nodes (would score 5,397 but only 45/266 live), `ScatterElements(reduction="max")` with BOOL updates (ORT rejects BOOL reduction max), pack4 int64 (cost 6589), and low-rank probe MLP/active Conv routes (not exact).

**Active Conv sub-5k probe**: single 30×30 Conv masks are impossible: every kernel shape with ≤480 dense params had identical local patches that must be both fill and non-fill. Active-window Conv reduced memory by targeting a 17×20 mask and opset-13 BOOL Pad. Necessary conflict checks found a budget-fitting `17×11 Conv + col threshold + 45 global probes` shape (estimated cost 4998), but linear training collapsed to thousands of errors; a scalar global threshold was not expressive enough to reproduce the masks. Static row/col and active threshold-map variants also had unavoidable patch conflicts under the sub-5k budget.

**Probe-MLP sub-6k probe**: built `train_task101_probe_mlp_mask.py` for a FP16 `46 probes → hidden → 17×20 mask` generator. Hidden-7 scores at cost 5831, but failed visible correctness (`0/266` direct verify); hidden-12 still failed and cost 7796. The active mask matrix has real rank 222, so very low-rank mask generation is not a viable exact replacement for the lookup table.

**Structural TopK/scatter ONNX probe**: `build_task101_structural_topk_scatter.py` compiles the decoded rule without any `[N≈266,K]` example table. It uses `source2 = color2 & dilate4(color2 & dilate4(color1))`, `target2 = color2 & ~source2`, `TopK` extraction for the ≤7 source-1 cells and ≤6 target component top-lefts, dynamic source-anchor/target-partner validation, and a rolling `ScatterElements` chain into a 17×20 fill mask. Latest simplified cost is 16,440 (memory 15,747 + params 693) and it verifies 266/266 vs expected and 266/266 vs `submission.zip`; it is a structural correctness proof, not the lowest-cost candidate.

**2026-06-09 structural W14 row/col candidate**: the current staged structural route lowers the live structural graph from 18,236 to 14,039 by processing only the generator-bounded 17×14 target surface, pruning dead initializers, removing identity source slice/pad nodes, dropping the duplicated second-anchor fill path, and replacing flat pair-delta validation with row/column deltas to avoid width-14 wrap false positives. Public `validate()` pair 3 is outside the generator width and needs a guarded 45-cell scatter patch; no-patch misses exactly those 45 cells. Full-gate interpretation: LIVE truth is 196,764/200,000, candidate truth is 196,854/200,000, and dual-truth attribution over the same corpus shows 0 LIVE-correct/candidate-wrong cases. This is more-correct-than-LIVE on the full generator corpus, not byte-equal compression.

**2026-06-09 sub-5k risk lookup pass**: active-width lookup variants can cross the 5k line only by giving up green-gate behavior. Plain active14 with safe scatter guards costs 5,040 and fails only the public width-21 case (265/266 visible). Capping the longest active14 rows to 60 or 52 positions drops MAX_WORDS from 21 to 20/18 and costs 4,996/4,908; both measure visible 264/266, truth 265/200,000, and ab 550/200,266. Removing the safe-index `Where` nodes gets cheaper (4,484–4,787) but false padding scatters clear real mask cells, dropping visible as low as 56/266. Hash-table shrinking below the 64-bucket/280-slot displaced layout failed placement; original 46 probes have no redundant coordinate under their existing basis, and a wider all-cell greedy probe search was worse (67 probes).

**2026-06-09 sub-3k / sub-1.5k partial ScatterND pass**: replacing the full mask+Pad+Where output tail with a single dynamic `ScatterND(input, indices, updates)` is the only tested route that crosses 3k. It patches ch0=0 and ch1=1 for selected fill cells; unmatched 46-probe keys select a zero-length dummy row and scatter zero-valued fallback updates into padding cell `(29,29)`, preserving identity. Shortest-row cuts score: 16 rows cost 1,209 (visible 16/266, truth 17/200,000, ab 502/200,266), 32 rows cost 2,042 (32/266, 33/200,000, ab 534/200,266), 61 rows cost 2,998 (61/266, 63/200,000, ab 592/200,266). Boundary: 62 shortest rows costs 3,005; 64 rows costs 3,019. Direct ScatterND is bad for long official rows because dynamic INT64 index tensors grow with max row length; the official4 probe cost 13,474.
