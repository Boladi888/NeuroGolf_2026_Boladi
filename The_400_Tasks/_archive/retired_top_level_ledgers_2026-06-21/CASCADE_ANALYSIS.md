# Cascade-Risk Analysis

> Generated by `tools/cascade_report.py` from `task_state.csv` (401 task rows). Identifies external sources whose failure would cascade across many tasks, ranked by pool size + LB-points exposure.

## What this is

`current_src` is the source that supplies a task's ONNX payload in the current submission. When many tasks share the same external source, a single Kaggle-side issue with that source (e.g., a cascade error from one bad ONNX in the pool) takes them all down at once. Conversely, writing an organic replacement for a single task in the pool gives a template for the rest.

**Suggested cascade-risk workflow:**

1. Pick the source with the largest pool whose tasks are mostly NotSolved (column `Solved` low vs `Tasks`).
2. From section 4, pick the 1-3 highest-cost tasks within that pool.
3. For each: write a numpy verifier → organic ONNX → only submit if the rule is a pure global transform (symmetry, periodic-fill, etc.). Anchor-based / template-matching organics tend to hit the silent-fail trap — see `Logs/lessons.md`.
4. Even if you don't submit, the organic prototype documents an exit path from the cascade-risk pool.
